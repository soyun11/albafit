# checklist.md — 4주 작업 체크리스트

> 매장 맞춤 알바 훈련 서비스 MVP (업종: 카페 1개로 축소)
>
> 쪼갠 3축:
> - **레이어 축**: 데이터 → 로직 → UI (아래에서 위로 쌓음)
> - **중요도 축**: 코어(A 대화 + B 평가)를 먼저, 설정·리포트는 뒤에
> - **완성도 축**: 뼈대(돌아가게) → 정확도(믿을 만하게) → 다듬기(써볼 만하게)
>
> 우선순위 원칙: **(1) 대화+평가 코어 → (2) 규칙 입력 → (3) 리포트(시간 남으면).**
> 가장 어려운 것(규칙→루브릭 변환, 평가자 신뢰성)을 앞 주차로 당긴다.

---

## 1주차 — 뼈대 & 데이터 (돌아가는 최소 골격)

**목표: 데이터 모델이 서고, 가장 어려운 "규칙 → 루브릭 변환"이 동작한다.**

### 데이터 레이어
- [ ] 프로젝트 셋업 (React + Express, 레포·환경변수·API 키 관리)
- [ ] 데이터 모델 정의
  - [ ] 매장(store): 링크 ID 단위, 로그인 없이 식별 — *영속성 없는 대신 링크가 키*
  - [ ] 규칙(rules) / 루브릭(rubric) / 시나리오(scenario) 스키마
  - [ ] 훈련 세션(session): 대화 로그·답변·평가결과·재시도 — *지금은 스키마만, 채우는 건 2주차*
- [ ] 매장 링크 발급·조회 API (로그인 없는 접근의 기반)

### 로직 레이어 (가장 어려운 것 먼저)
- [ ] **규칙 → 루브릭 변환 LLM 호출** ★ 최난이도, 최우선
  - [ ] 프롬프트: "이 매장 규칙을 평가용 체크리스트로 쪼개라. 각 항목 must/nice 구분, 좋은예·나쁜예 포함"
  - [ ] 출력 JSON 강제 (`[{기준, 필수여부, 좋은예, 나쁜예}]`)
  - [ ] 카페 시나리오 3개(지연·품절·규칙위반)에 대해 손으로 규칙 넣고 루브릭 뽑히는지 확인
- [ ] 업종 템플릿(질문 세트) 정의 — 카페용: 환불/교환·지연·품절·금지표현 질문

### UI 레이어 (골격만)
- [ ] 화면 라우팅 골격 (사장님/알바 경로 분리, 5개 화면 빈 페이지)
- [ ] 규칙 입력 폼 (자연어 textarea + 업종 템플릿 질문 표시) — *제출만 되면 됨, 예쁨은 나중*

**1주차 완료 기준**: 규칙을 텍스트로 넣으면 → 루브릭 JSON이 콘솔에 찍힌다.

---

## 2주차 — 코어 로직 (A 대화 + B 평가가 실제로 돈다)

**목표: 알바가 AI 손님과 대화하고, 답변이 루브릭으로 채점되어 분기된다. 제품의 심장.**

### 로직 레이어 — 기능 A (AI 손님)
- [ ] **AI 손님 대화 LLM 호출**
  - [ ] 시스템 프롬프트: 페르소나 + 시나리오 상태(주문상태·손님기분·경과턴) 주입
  - [ ] 저렴·빠른 모델 사용 (호출이 잦으므로)
  - [ ] 대화 히스토리를 매 호출에 전달 (상태 유지 — LLM은 기억이 없음)
  - [ ] **분기 처리**: 알바 답변에 따라 손님 반응이 달라지게 (1회성 챗봇과 구분되는 지점)

### 로직 레이어 — 기능 B (AI 평가자)
- [ ] **AI 평가자 LLM 호출** ★ 신뢰성 핵심
  - [ ] 입력: (루브릭, 시나리오 맥락, 대화 히스토리, 알바 답변)
  - [ ] 신중한 중상급 모델 사용
  - [ ] **출력 JSON 강제**: `{충족여부, 빠진기준[], 피드백, 개선문장}` — 마크다운·서두 금지
  - [ ] 근거를 규칙 인용으로 대게 ("②번 미충족: 'ETA 안내' 규칙")
- [ ] A와 B를 하나의 턴 루프로 연결 (손님 발화 → 알바 답변 → 평가 → 분기)
- [ ] **미충족 → 재입력 루프**: 개선 문장 제시 후 같은 턴 다시 시도
- [ ] 충족 → 다음 턴 또는 훈련 완료 처리

### 데이터 레이어
- [ ] 훈련 세션 저장 (대화·답변·평가·재시도 실제 기록 시작)

**2주차 완료 기준**: 알바가 시나리오 하나를 골라 손님과 몇 턴 대화하고, 답변마다 통과/미통과 + 개선문장을 받는다. (UI는 거칠어도 됨)

---

## 3주차 — 신뢰성 & 완성도 (믿을 만하고 써볼 만하게)

**목표: 평가자가 신뢰할 만해지고, 코어 화면(대화·규칙입력)이 실제로 쓸 만해진다.**

### 정확도 (신뢰성)
- [ ] **평가자 캘리브레이션** ★ (human-in-the-loop)
  - [ ] 사장님이 초기 평가 결과 몇 개를 검토·교정하는 화면/흐름
  - [ ] 오답 케이스 모아 루브릭·프롬프트 다듬기
  - [ ] 엣지 케이스 테스트 (빈 답변, 무관한 답변, 규칙에 없는 얘기)

### UI 레이어 (코어 화면 다듬기)
- [ ] **훈련 대화 화면** ★ 인라인 체크리스트 피드백
  - [ ] 카톡 형태 채팅 UI (손님 말풍선 / 알바 입력)
  - [ ] 답변 아래 **항목별 ✓/✗ 표시** ("✓ 사과 / ✗ 대기시간 안내 / ✓ 금지표현 없음")
  - [ ] 개선 문장 + "다시 답하기" 버튼
- [ ] **규칙 입력 + 루브릭 승인 화면** ★
  - [ ] 자연어 입력 → AI가 정리한 루브릭을 **"이렇게 정리했어요, 맞나요?"** 로 보여주고 승인/수정
  - [ ] 승인 루프 (수정 시 재생성)
- [ ] 시나리오 선택 화면 (카드 3개)
- [ ] 훈련 결과 요약 화면 (통과·재시도·자주 놓친 기준)

**3주차 완료 기준**: 사장님이 규칙 넣고 루브릭 승인 → 링크 전달 → 알바가 대화·교정까지 끊김 없이 흐른다. 평가가 대체로 믿을 만하다.

---

## 4주차 — 다듬기 & 여유분 (전체 흐름 완결)

**목표: 초안 자동생성·승인 UX를 얹고, 전 흐름을 QA하고, 남으면 리포트/사진입력.**

### 자동화 UX (초안 생성)
- [ ] 규칙·시나리오 초안 자동 생성 (업종 템플릿 → AI 초안)
- [ ] AI 초안 승인/수정 UX 다듬기

### 리포트 (중요도상 후순위)
- [ ] 사장님 결과 확인 화면 (알바별 훈련·약점 리포트) — *재방문 유도 확장 1순위*

### QA & 마감
- [ ] 전체 흐름 통합 테스트 (사장님 설정 → 알바 훈련 → 결과 확인)
- [ ] 매장 링크 접속·로그인 없는 경로 점검
- [ ] 발표 시나리오용 데모 데이터(카페 예시) 세팅
- [ ] 경쟁 비교표·문제정의 슬라이드 정리 (plan.md 1-4 활용)

### 여유 시 (v1.5 착수)
- [ ] 매뉴얼 사진 → 규칙 초안 (OCR/비전) — 있으면 입력 마찰 크게 감소

**4주차 완료 기준**: 데모 가능한 완결된 v1. "규칙 입력 → 훈련 → 리포트"가 한 번에 보여진다.

## 축별 요약 (한눈에)

| 주차 | 레이어 무게중심 | 중요도 | 완성도 |
|---|---|---|---|
| 1주 | 데이터 + 난이도 높은 로직 | 코어 토대(루브릭 변환) | 뼈대 |
| 2주 | 로직 (A+B) | **코어** | 뼈대→돌아감 |
| 3주 | UI + 정확도 | 코어 화면 | 정확도 |
| 4주 | UI + 통합 | 설정 자동화·리포트 | 다듬기 |

## 리스크 메모 (막히면 여기부터)
- 루브릭 변환이 부정확 → 1주차에서 막힘. 프롬프트에 좋은예/나쁜예를 더 구체화.
- 평가자가 오채점 → 2~3주차 핵심 리스크. 루브릭을 더 이분법적으로, 근거 인용 강제, 사장님 캘리브레이션.
- 시간 부족 → 리포트(4주)와 사진입력(v1.5)부터 버린다. 코어(A+B)와 규칙입력은 절대 안 버림.
