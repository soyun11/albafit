# staff-account-recovery.md — 알바 계정 정보를 잃어버렸을 때 복구

> `docs/rubric-reuse.md`와 같은 방식으로 기록한다. 근거: 사용자가 대시보드 통합 작업 중 지적한 실사용 시나리오, 2026-07-22.

## 왜 만들었나

사장님이 알바 계정을 만들 때(`POST /api/stores/me/staff`) 이메일과 초기 비밀번호를 직접 정해서 알바에게 알려주는 구조다. 그런데 애초엔:
- 대시보드 알바 목록에 이메일이 안 보였다 — "이번에 만든 계정" 목록(세션 로컬)에서만 잠깐 보이고 새로고침하면 사라졌다.
- 비밀번호를 사장님이 잊어버리거나 알바에게 잘못 전달했을 때, 다시 확인하거나 바꿀 방법이 전혀 없었다.

1차로 이메일 표시 + 비밀번호 재설정(표 안 인라인 펼침 폼)을 만들었는데, 사용자가 "UI가 불편하다"고 다시 지적했고 "이메일도 같이 수정 가능하게", "비밀번호를 볼 수 있게"도 요청했다. 이 문서는 그 피드백을 반영한 2차 개정이다.

## 결정

| 논점 | 결정 | 이유 |
|---|---|---|
| 비밀번호를 "볼 수 있게" | **불가능 — 대신 새 비밀번호로 덮어쓰기만 가능**(기존 결정 유지) | 비밀번호는 bcrypt 해시로 저장돼 서버조차 원문을 복원 못 한다(단방향). 원문 저장은 보안 사고 위험이 커서 금지된 관행 — 이건 이 프로젝트만의 제약이 아니라 로그인 시스템의 일반 원칙이다. 사장님이 새로 정한 값은 사장님이 아니까 "보는 것"과 실질적으로 같은 효과를 낸다. |
| UI 방식 | 표 안 인라인 펼침 행 → **모달(팝업)**로 교체 | 인라인 펼침은 다른 행들이 밀려나고 산만하다는 피드백. 이 프로젝트에 모달 패턴이 아직 없어서 새로 만들지만, 기존 디자인 토큰(glass 카드, btn-primary/btn-ghost)을 그대로 재사용해 톤을 맞춘다. |
| 수정 범위 | 이메일 + 비밀번호(선택) 한 모달에서 같이 | 사용자가 "메일이랑 비밀번호 둘 다 수정 가능하게"를 명시적으로 요청. 비밀번호 칸은 비워두면 안 바뀌게(선택 입력) — 이메일만 고치고 싶을 때 비밀번호를 다시 정할 필요는 없어야 한다. |
| API | 기존 `PATCH /me/staff/:staffId/password`를 `PATCH /me/staff/:staffId`로 일반화, body에 `email`/`newPassword` 둘 다 선택적으로 받음 | 계정 하나를 고치는 논리적으로 같은 액션이라 엔드포인트를 굳이 둘로 안 나눈다. 이메일 중복(P2002)은 계정 생성 라우트와 같은 방식으로 처리. |

## 구현·검증

### 구현
- `server/src/routes/stores.js` — `PATCH /me/staff/:staffId/password` → `PATCH /me/staff/:staffId`로 일반화. `email`/`newPassword` 둘 다 선택적, 최소 하나는 필요. 이메일 중복(P2002) 처리 추가.
- `src/components/StaffEditModal.jsx`(신규) + `StaffEditModal.css`(신규) — 이 프로젝트 첫 모달. `position: fixed` 반투명 배경 + 중앙 정렬 카드, 이메일(항상 필수)·새 비밀번호(선택, 비우면 유지) 입력 + 취소/저장.
- `src/components/OwnerDashboard.jsx` — 인라인 펼침 행(`Fragment`, `resetTarget` 등) 제거하고 "계정 수정" 버튼 → 모달 오픈으로 교체. 저장 성공 시 목록의 이메일을 즉시 갱신(새로고침 불필요).
- `src/components/OwnerDashboard.css` — 이제 안 쓰는 `.reset-password-row`/`.reset-password-form`/`.btn-primary-sm` 삭제.
- 서버 테스트 70개 + 루트 12개 + lint + build 통과.

### 브라우저 확인 (`claude-in-chrome`, 기존 테스트 계정)
- "계정 수정" 클릭 → 모달이 화면 중앙에 뜨고 배경이 어두워짐(인라인 펼침보다 훨씬 깔끔하다는 사용자 피드백 반영).
- **이메일만 변경** → 저장 → 목록에 즉시 반영, `curl` 로그인으로 새 이메일이 실제로 통하는 것 확인.
- **비밀번호만 변경**(이메일 그대로) → 저장 → `curl` 로그인으로 새 비밀번호가 실제로 통하는 것 확인, 이메일은 그대로 유지됨.
- 콘솔 에러 없음.

이슈(사용자 요청) 완료 기준 — "이메일·비밀번호 둘 다 수정 가능, UI가 편해야 함" — 둘 다 확인됨. "비밀번호를 보는 것"은 해시 저장 특성상 불가능하다는 점을 사용자에게 설명하고 "새 값으로 덮어쓰기"로 대체하기로 합의.
