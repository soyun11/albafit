# nav-unification.md — 로그인 화면 상단 네비게이션 통일 (AppNav)

> `docs/auth-improvement-plan.md`, `docs/store-creation-improvements.md`, `docs/guest-try-feature.md`와 같은 방식으로 기록한다.

## 왜 손댔나

로그인 이후 화면(대시보드·기준 관리·알바 초대·시나리오 선택·훈련 세션)이 각자 따로 상단 `<nav>`를 코딩하고 있었다. 그러다 보니:
- 화면마다 링크 구성이 달랐다 — 예를 들어 대시보드에서 "기준 관리"·"리포트"로 바로 못 넘어가고, 일부는 클릭해도 아무 동작 안 하는 장식용 `<span>`이었다.
- 알바 리포트는 대시보드 안 표(테이블)로만 볼 수 있었고, 독립된 화면·독립된 진입 경로가 없었다.
- 로그인 후 첫 화면부터 서비스 정체성(사장님/알바)이 상단바에서 드러나지 않는다는 지적이 있었다.

## 결정

| 대안 | 비고 |
|---|---|
| 화면마다 nav를 계속 따로 유지 | 기존 상태. 링크 불일치·중복 코드가 계속 쌓임 |
| 사장님 모드/알바 모드 토글 UI | 논의 후 기각 — 서비스 정체성을 상단 토글보다 "매장 없이 체험" 같은 진입 경로로 드러내는 게 더 낫다고 판단(별도로 `docs/guest-try-feature.md`에서 진행) |
| **공유 `AppNav` 컴포넌트로 통일 (채택)** | role(`owner`/`staff`)별 링크셋 하나만 정의, 화면은 `current` 키만 넘기면 됨 |

## 구현

### `src/components/AppNav.jsx` + `.css` (신규)
- `role` prop으로 링크셋 결정: `owner` → 대시보드/기준 관리/리포트/알바 관리, `staff` → 시나리오 선택.
- `current` prop과 링크 key가 같으면 `.active` 클래스로 강조.
- `children` slot — 화면별 추가 액션 버튼을 넣는 자리 (대시보드 "+ 알바 초대", 훈련 세션 "훈련 종료").
- 이동은 전부 `onNavigate(key)` 콜백 하나로 위임. `App.jsx`에 새 `handleNavigate(key)` 디스패처를 만들어 `home`/`rubricManage`는 특수 처리(각각 `goHome()`, 서버에서 루브릭 재조회 후 이동)하고 나머지는 `setScreen(key)`.

### `src/components/ReportList.jsx` + `.css` (신규)
대시보드 안에 박혀 있던 알바 현황 표(진행률·최근 점수·상태)를 독립 화면으로 분리했다. AppNav의 "리포트" 링크로 바로 진입, 행 클릭 시 기존 `FeedbackReport`로 이동하는 흐름은 그대로 유지.

### 적용 화면
`OwnerDashboard`, `RubricApproval`(대시보드에서 재방문하는 관리 모드에 한해 — 온보딩 중 최초 승인 흐름은 기존 `StepSidebar` 유지, `onDone` prop 유무로 두 모드 분기), `StaffInvite`, `ScenarioSelect`, `TrainingSession`까지 전부 각자의 구식 `<nav>`를 걷어내고 `AppNav`로 교체. 각 화면 CSS에서 죽은 nav 관련 셀렉터(`.dashboard-nav`, `.invite-nav`, `.scenario-nav*`, `.session-nav` 등)도 같이 정리했다.

## 발견한 버그 — 화면 전환 시 스크롤 위치가 안 풀림

전 화면 검증 중 알바 초대 화면(`StaffInvite`) 스크린샷에서만 상단 AppNav 바가 안 보이는 걸 발견했다. `.app-nav`는 DOM에 정상적으로 있었지만 `getBoundingClientRect()`로 보니 `y: -60`— 뷰포트 위로 밀려나 있었다.

**원인**: 이 앱은 라우터 없이 `App.jsx`의 `screen` state 하나로 화면을 통째로 갈아끼우는 구조다. 루브릭 승인 화면(카드가 길어서 스크롤이 필요)에서 아래로 스크롤한 채로 "알바 초대하기"를 눌러 다음 화면으로 넘어가면, 브라우저는 스크롤 위치를 그대로 유지한다. 새로 마운트된 화면은 항상 맨 위(스크롤 0)부터 보여야 하는데, 실제로는 이전 화면의 스크롤 위치가 그대로 남아 새 화면 최상단의 nav 바가 화면 밖으로 밀려났다. 화면이 바뀔 때마다 재현되는 문제라 알바 초대뿐 아니라 모든 화면 전환에 잠재해 있었다.

**수정**: `App.jsx`에 `screen`이 바뀔 때마다 `window.scrollTo(0, 0)`을 실행하는 `useEffect`를 추가.

```jsx
useEffect(() => {
  window.scrollTo(0, 0)
}, [screen])
```

## 검증
- Playwright: 사장님 온보딩(회원가입 → 업종선택 → 규칙입력 → 루브릭 3개 승인) → "알바 초대하기" → 계정 생성 → AppNav로 대시보드 → 리포트 → 기준 관리 → 알바 관리 순회, 알바 계정으로 로그인 → 시나리오 선택 → 훈련 시작까지 전 구간 콘솔 에러 0건.
- 위 흐름에서 알바 초대 화면 스크린샷만 AppNav가 안 보이는 걸 발견 → `getBoundingClientRect()`로 `y: -60` 확인 → 스크롤 리셋 수정 후 재검증 → `y: 0`, 스크린샷에서도 "알바 관리"가 active 상태로 정상 표시되는 것 확인.
- `npm run lint` 통과.

## 확장 — 로그인 전 화면까지 AppNav 범위 넓히기 (같은 날 후속 작업)

1차 적용 후 사용자 피드백: "상단 메뉴바는 언제든지 떠 있어야 해." 로그인 이후 화면에만 있던 AppNav를 로그인 전(체험하기)·온보딩 중(아직 매장 안 만든 사장님) 화면까지 넓혔다.

### AppNav 확장
- `role`이 `'owner'`/`'staff'`가 아니면(로그인 전) 오른쪽 버튼이 계정/로그아웃 대신 로그인/회원가입으로 바뀌는 `role="guest"` 상태 추가.
- `disabledKeys` prop 추가 — 링크는 그대로 보여주되(있다는 걸 알 수 있게) 클릭은 막고 싶을 때 씀. 업종선택 화면(아직 매장이 없어서 대시보드·기준관리·리포트·알바관리로 가봤자 빈 상태)에 사용.

### 사장님 온보딩 3화면(업종선택/규칙입력/루브릭승인)
기존엔 각 화면이 로고만 있는 미니 `<nav>`를 따로 갖고 있었다. `StepSidebar`(왼쪽 1/2/3 진행 표시)는 그대로 두고, 그 미니 nav를 AppNav로 교체했다. 매장은 업종선택 화면에서 "다음"을 누르는 순간 생성되므로, 실제로 링크를 비활성화해야 하는 화면은 업종선택 하나뿐이다.

### 체험하기(GuestTry)
- 자체 `<nav className="guest-nav">`를 `<AppNav role="guest" />`로 교체, "비회원 체험 · 저장되지 않아요" 안내는 nav 밖 배지(`.guest-mode-banner`)로 옮겼다.
- "실제 UI와 비슷하게 해달라"는 요청으로 CSS 수치를 실제 화면 기준으로 다시 맞췄다 — 마스코트 76px(IndustrySelect 기준), 카드 그리드 gap/padding(ScenarioSelect 기준), 채점 기준 카드(RubricApproval `.criterion-card` 기준), 대화 화면 그리드 비율 1.4fr/1fr·말풍선 패딩(TrainingSession 기준). 새 class를 만들지 않고 기존 `guest-*` 클래스의 값만 실제 화면과 동일하게 맞춰서, 코드는 별개 파일이지만 화면은 거의 같은 느낌이 나게 했다.

### 랜딩페이지 — 사이트 구조를 보여주는 상단 링크
"메인화면에서 사용자들이 사이트에 어떤 기능이 있는지 모른다"는 지적으로, 기존에 이미 있던 콘텐츠 섹션 3개(`albafit이 다른 이유` / `사용 방법` / `교육 전·후`)에 id를 달고 상단바에 스크롤 이동 링크(`왜 albafit인지` / `이용 방법` / `효과`)를 추가했다. 개발용 "전체 화면 목록" 링크는 남겨두되 옅은 밑줄로 스타일을 분리해 실제 기능 링크와 구분했다.

### 검증
- Playwright: 랜딩 → 3개 앵커 링크 클릭 시 해당 섹션으로 스크롤 이동 확인. 체험하기 → 업종·시나리오 선택 → 규칙 입력 → 실제 Gemini 채점기준 → 대화 3턴까지 콘솔 에러 0건. 온보딩 업종선택 화면에서 대시보드 링크가 `disabled` 상태인 것 확인, 규칙입력·루브릭승인 화면에서 AppNav+StepSidebar 동시 렌더 확인.
- `npm run lint` 통과.
