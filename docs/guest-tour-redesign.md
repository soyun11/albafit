# guest-tour-redesign.md — 체험하기를 가이드 투어로 전환

> `docs/rubric-reuse.md`와 같은 방식으로 기록한다. 관련: `soyun11/hub#17`(게스트 체험모드 400 버그, 이 작업으로 해소됨), 2026-07-27 대화.

## 왜 만들었나

로그인 없는 "체험하기"(`GuestTry.jsx`)는 원래 규칙을 직접 타이핑 → AI가 루브릭 생성 → 손님과 자유롭게 대화(AI 평가) 흐름이었다. 처음엔 여기에 로그인 훈련과 똑같은 하트·재입력 시스템을 이식하려 했으나(task-planner로 결정표까지 짬), 논의 중 더 간단한 방향으로 바뀌었다: **어차피 처음 써보는 사람에게 자유 입력은 진입장벽이고, 부스 전시에서 방문객이 몇 초 안에 "이런 서비스구나"를 느끼는 게 목적**이라면, 타이핑 없이 버튼만 누르며 미리 짜둔 좋은 예시를 보여주는 가이드 투어가 더 낫다는 결론.

## 결정

| 논점 | 결정 | 이유 |
|---|---|---|
| 규칙 직접 입력 | **제거** — 업종·시나리오별로 미리 써둔 예시로 대체 | 타이핑은 부스 방문객에게 진입장벽. 이미 오늘 `defaultScenarios.js`에 6개 업종 × 3개 시나리오를 정성껏 써뒀으니 그 내용을 그대로 재사용 |
| 손님과의 대화 | **자유 타이핑 제거, 대신 손님↔직원이 실제로 주고받는 미니 대화를 스크립트로 재생** — 손님 오프닝 → (버튼) 직원의 모범 답변 → 손님의 반응 대사 → AI 트레이너가 "이 포인트를 챙겼어요" 코멘트 → (버튼) 다음 포인트로 반복 | 처음엔 "모범 답변만 나열해서 보여주기"로 만들었으나, 사용자가 "정해진 시나리오를 따라가는 느낌"을 원해서 손님 반응 대사를 각 포인트마다 추가해 진짜 대화처럼 이어지게 다시 만들었다. 자유 입력이 없으니 평가할 것도, 재입력·하트도 필요 없다는 원래 결론은 그대로 유지 |
| 버튼에 클릭 유도 표시 | 처음엔 버튼 텍스트 안에 👆를 넣고 제자리에서 통통 튀게(bounce) 했다가 → 사용자가 "포인터가 움직이면서 가리켜야" 한다고 요청 → 버튼 밖에서 안으로 미끄러져 들어와 눌렀다 빠지는(scale down) 애니메이션으로 교체(`guestCursorMove`) → 처음엔 🖱️(마우스 이모지)를 썼는데 일부 폰트에서 아주 연하게 렌더링돼 잘 안 보여서 👆로 교체 → 이모지는 폰트·OS마다 렌더링이 갈려 신뢰할 수 없다고 판단, CSS `border` 삼각형으로 직접 그린 주황색 포인터로 교체 → 사용자가 원하는 모양의 스크린샷(실제 커서 화살표, 흰 바탕+주황 테두리+글로우)을 전달해 최종적으로 **커서 화살표 모양 SVG**(`polygon` + 흰 채우기 + 주황 `#f5911e` 테두리 + `drop-shadow` 글로우)로 교체(`CursorHint` 공용 컴포넌트) → 투어 버튼뿐 아니라 **1단계 업종 선택 카드·2단계 시나리오 카드의 첫 번째 항목에도 동일하게 적용** | 이모지 대신 직접 그린 도형을 쓰면 폰트·OS와 무관하게 항상 같은 모양·색으로 렌더링된다. SVG는 사용자가 준 참고 이미지와 동일한 커서 실루엣을 정확히 재현할 수 있어 CSS 삼각형보다 나음. 사용자가 "커서가 두 개인가" 헷갈렸던 것은 브라우저 자동화 테스트 중 실제 OS 커서와 겹쳐 보인 것으로, 실사용 환경에는 해당 없음(검증 시 자동화 커서를 대상 요소에서 hover로 비켜두고 스크린샷 확인). 처음 화면(업종 선택)부터 동일한 포인터로 안내해달라는 요청에 따라 3단계 전부에 같은 컴포넌트를 재사용 |
| AI 호출 | **전부 제거** — 콘텐츠가 전부 정적 텍스트라 서버 호출 자체가 필요 없음 | `guest.js` 파일 상단에 있던 "인증 없이 유료 LLM 직접 호출, 나중에 IP 제한 필요"라는 TODO가 이 변경으로 완전히 해소된다(임시방편이 아니라 구조적으로 비용 노출이 없어짐) |
| 콘텐츠 소스 | `server/src/lib/defaultScenarios.js`의 내용을 `src/lib/guestTourContent.js`(프론트 전용, 신규)로 그대로 옮겨 적는다 | 프론트·백엔드가 별도 번들이라 서버 파일을 프론트가 직접 import할 수 없다. 내용은 오늘 이미 검증된 것을 그대로 복사하는 수준이라 새로 작성하는 비용이 없다 |
| 400 버그(soyun11/hub#17) | **이 작업으로 자연 해소** — 자유 타이핑이 없으니 "다음 손님 메시지가 붙기 전에 또 제출"하는 레이스 컨디션 자체가 발생할 수 없음 | 원인(타이핑 후 제출 API 호출 중 타이밍)이 구조적으로 없어짐. #17에서 이 항목은 제거 |
| 버튼 안내 방식 | 다음 액션 버튼에 `pulse` 애니메이션(커졌다 작아졌다) 클래스 추가 | 튜토리얼처럼 "여기를 누르세요"를 시각적으로 안내. 새 라이브러리 없이 CSS `@keyframes`만으로 충분 |
| 정리 대상 | `server/src/routes/guest.js`, `server/src/lib/industryScenarios.js` 삭제. `customerAgent.js`의 `SCENARIOS` 맵·`getOpeningLine`·`getCustomerReply`(scenarioType 키 버전) 삭제. `src/lib/industries.js`의 `INDUSTRY_SCENARIOS` 삭제 | 전부 guest.js 전용으로만 쓰이던 코드라 guest.js를 없애면 완전히 죽은 코드가 된다(각각 grep으로 다른 소비자 없음을 확인). `sessions.js`가 쓰는 `getOpeningLineForScenario`/`getCustomerReplyForScenario`는 별개 함수라 안 건드림 |

## 추가 결정 (규칙 확정 → 시나리오 분리 단계)

체험 투어가 업종 선택 후 바로 시나리오로 넘어가다 보니, 제품의 핵심(사장님이 규칙을 입력하면 AI가 시나리오로 나눠준다)이 투어에서 안 보인다는 피드백. 실제 타이핑은 여전히 없이(가이드 투어 원칙 유지), "규칙 화면을 보여주고 → 확정 버튼 클릭 → 시나리오로 나뉘는 것"까지 보여주는 단계를 추가.

| 논점 | 결정 | 이유 |
|---|---|---|
| 새 단계 위치 | `industry` → **`rules`(신규)** → `scenario` → `tour`, 진행률 `N/4`로 변경 | 실제 사장님 플로우(업종 선택 → 규칙 입력 → 확정 → 시나리오 생성) 순서를 그대로 따라감 |
| 규칙 화면 콘텐츠 | 새로 쓰지 않고 `RulesInput.jsx`의 `INITIAL_RULES_BY_INDUSTRY`(업종별 예시 규칙 카드, 이미 6개 업종용으로 작성됨)를 `export`해서 그대로 재사용 | 이미 검증된 실제 온보딩 화면 콘텐츠라 중복 작성할 이유가 없음. 값이 갈리면 두 화면이 따로 놀 위험도 없앰(한 군데서만 관리) |
| 규칙 화면 상호작용 | 카드는 읽기 전용(토글·수정 불가) — 실제 `RulesInput`과 달리 편집 UI는 안 둠. "이 기준으로 확정하기" 버튼 하나만 클릭(가이드 커서) | 체험 투어는 여전히 클릭만으로 흐름을 보여주는 게 목적. 편집 가능하게 하면 자유 입력을 다시 들이는 셈이라 원래 원칙과 충돌 |
| 확정 → 분리 연출 | 버튼 클릭 시 약 0.7초 "AI가 규칙을 분석해서 상황별로 나누는 중..." 짧은 로딩 표시 후 시나리오 단계로 이동. 시나리오 단계 제목도 "규칙을 이 상황들로 나눴어요"로 변경 | 즉시 전환하면 "나뉘었다"는 느낌이 안 산다. 짧은 로딩 한 번으로 AI가 실제로 뭔가 처리했다는 느낌을 주되, 과하게 길게 끌지 않음 |

## 추가 결정 (사장님 1→2→3 온보딩 + 알바 초대까지 한 파이프라인으로)

"규칙 확정 → 시나리오 분리"만 보여주는 걸론 부족하다는 피드백 — 실제 서비스는 `StepSidebar.jsx` 기준 사장님 온보딩이 **1단계(업종선택·매뉴얼입력) → 2단계(규칙확인) → 3단계(루브릭승인)** 세 단계고, 승인이 끝나면 `StaffInvite.jsx`로 알바 계정을 만든 다음에야 알바가 로그인해서 훈련을 시작한다(`RubricApproval.jsx`→`onInvite`). 체험 투어도 이 실제 파이프라인 전체를 하나로 이어서 보여주기로 함.

| 논점 | 결정 | 이유 |
|---|---|---|
| 단계 구성 | `industry`(1) → `rules`(2) → **`rubric`(3, 신규)** → **`invite`(4, 신규)** → `scenario`(5, 알바 관점 전환) → `tour`(6) — 진행률 `N/6` | 실제 사장님 화면 순서(`StepSidebar`의 1/2/3) + 알바 초대 + 알바 로그인 후 훈련까지, 한 서비스 안의 두 역할(사장님→알바)이 이어지는 걸 그대로 보여줌 |
| 루브릭 승인 화면 콘텐츠 | 새로 안 쓰고 `guestTourContent.js`에 `bad_example` 필드를 다시 채워 넣어(`server/src/lib/defaultScenarios.js`에서 그대로 복사) `RubricApproval.jsx`처럼 시나리오 탭별로 기준(✓ good / ✗ bad, 필수·선택 배지)을 보여줌 | 실제 화면과 같은 정보 밀도로 보여줘야 "이게 진짜 어떻게 동작하는지" 체감됨. 값은 서버 파일이 원본이라 복사만 하면 됨(새로 작성 없음) |
| 루브릭 승인 상호작용 | 탭마다 읽기 전용으로 기준을 보여주고 "이 기준으로 승인하기" 버튼만 클릭(가이드 커서) — 수정·필수/선택 토글은 없음. 3개 다 승인하면 "알바 초대하기 →" | 실제 화면은 수정 가능하지만, 체험 투어는 여전히 클릭만으로 흐름을 보여주는 게 목적(자유 입력 없음 원칙 유지) |
| 알바 초대 화면 | `StaffInvite.jsx`를 흉내낸 미리보기 — 이름/이메일/초기 비밀번호 필드에 예시 값이 이미 채워진 채 `disabled`로 표시(타이핑 불가), "알바 계정 만들기" 버튼만 클릭 가능(가이드 커서). 클릭하면 0.6초 로딩 후 "계정이 만들어졌어요" 카드 표시 | 실제 폼처럼 보이되 여전히 정적 투어 원칙(타이핑 없음)을 지킴. `disabled` input이 "이미 입력된 상태"를 자연스럽게 보여줌 |
| 알바 관점 전환 | `invite` 완료 카드의 "이제 알바 입장에서 볼까요? →" 버튼을 눌러야 `scenario` 단계로 넘어감. `scenario` 단계 제목도 "이제 알바가 로그인하면"으로 변경 | 사장님→알바로 역할이 바뀌는 지점을 명확히 표시해야 헷갈리지 않음 |
| 뒤로가기 | 각 단계는 항상 바로 이전 단계로 돌아감(`rubric`→`rules`, `invite`→`rubric`, `scenario`→`invite`) | 파이프라인 순서를 그대로 따라가는 게 목적이라 단계를 건너뛰는 뒤로가기는 오히려 혼란 |
| 매장 매뉴얼 텍스트 입력 화면 | `industry` 단계(1/6) 안에 병합 — 실제 `IndustrySelect.jsx`가 업종 선택 그리드와 매뉴얼 텍스트칸을 같은 화면에 두는 것과 동일하게, 업종 카드를 클릭하면(선택 표시만 되고 바로 안 넘어감) 그 아래 "+ 매장 매뉴얼 · 규정 입력" 칸이 나타나며 예시 텍스트가 이미 채워진 채(읽기 전용) 보여진다. "다음 →"을 눌러야 규칙확인(2/6)으로 이동 | 사용자가 "사장님이 텍스트로 입력하는 화면"이 빠졌다고 지적 — 실제 서비스는 이게 STEP1의 일부라 새 단계 번호를 만들 필요 없이 1/6 화면을 확장하는 게 맞음. 예시 텍스트는 새로 쓰지 않고 `rules`의 카드 예시 중 앞 2개를 문장으로 이어붙여 재사용(`manualPreview`) — "이 텍스트를 AI가 읽어서 옆 카드로 정리한다"는 인과관계가 자연스럽게 보임 |
